你有没有过这种瞬间——

正在Claude Code里写得正顺，突然发现某个功能在Codex里表现更好；或者Grok Build的某个能力刚好能解决当前卡点。于是你打开另一个工具，然后开始重新解释背景、贴代码、复述刚才的决策……

几分钟就过去了，思路也被打断了。

其实大部分人解决这个问题的方式，还是「复制 + 粘贴 + 自己总结」。结果往往是：细节丢了、语气变了、工具调用记录也没了。

最近出现的一个小工具，直接把这个问题砍掉了。

它叫 **seshport** 。

![](https://r2.jeanjan.kdns.fr/pictures/img-1e951fb201.jpeg)

一句话说明白：它能把你当前的编程会话，完整迁移到另一个AI编程工具里，保留用户和助手的对话、工具调用结果，几乎不丢信息。

目前支持：

  * • Claude Code
  * • Codex
  * • Grok Build

### 它到底解决了什么痛点

以前切换工具，你大概要做这些事：

  1. 1\. 自己总结当前进度
  2. 2\. 把关键代码和文件路径复制过去
  3. 3\. 重新说明「我为什么这么做」
  4. 4\. 祈祷对方能接上你的思路

seshport换了一种做法。

你在当前工具里直接输入 `/seshport`，它会给你一条恢复命令。打开目标工具，粘贴那条命令，会话就带着完整历史重新出现了。

不是总结，是原始对话记录转过去。

作者特意做过测试：在一个会话里埋了个暗号，迁移到另一个工具后，对方依然能准确回忆起来。这说明它传的是原文，不是压缩后的摘要。

### 实际怎么用

安装很简单，一行命令就行：
```

curl -fsSL https://raw.githubusercontent.com/Harshil-Jani/seshport/main/install.sh | sh
```

也支持 npm、pip、cargo、Homebrew，以及直接下预编译二进制。

装好之后，把对应的命令文件拷到工具目录里（Claude 和 Codex 各有一份）。

之后的日常操作就变成：

  * • 在Claude Code里敲 `/seshport`
  * • 它会告诉你：去Codex执行某条 resume 命令
  * • 打开Codex，粘贴，会话就过来了

反过来也一样。

命令行模式也支持，比如：
```

seshport claude codex   # 把最新的Claude会话迁到Codex  
seshport codex          # 自动识别并给出恢复命令
```

### 它为什么比「复制粘贴」强

有几个细节值得注意：

第一，它用的是**原生恢复** ，不是把一大段文字塞进新对话的开头。目标工具会把历史当成真正的会话记录来渲染，后续交互更自然。

第二，工具调用被展平成可读文本。你之前跑过的命令、看过的输出，都会以清晰的形式保留下来，而不是变成一堆看不懂的JSON。

第三，每个迁移都会带上一个简短的归属说明，告诉新工具「这段历史来自哪里」，避免上下文混乱。

当然也有边界：

  * • 非常短的对话，直接手动贴可能更快
  * • 一些平台私有的内部状态（比如加密的思考过程）会被去掉，这是刻意设计，保证跨工具兼容

整体思路很干净：只传「真正有价值的对话内容」，把平台差异的部分丢掉。

### 适合谁用

如果你同时在用两个以上的AI编程工具，并且经常因为某个工具在特定场景更强而想切换，这个工具基本就是为你准备的。

特别是：

  * • 习惯在Claude Code里深度思考，偶尔需要Codex的某个能力
  * • 喜欢Grok Build的某些交互，但主要工作流在Claude
  * • 团队里不同人用不同工具，需要把会话交接出去

它解决的不是「功能更强」，而是「切换时的摩擦成本」。

现在AI编程工具越来越多，每个都有自己的长处。真正卡人的，往往不是能力本身，而是「切换太贵」。

seshport把这个成本压到了几秒钟。
