## 实操体检攻略：如何准确测出你的“64 MiB 新体质”？

空间虽然全面放开，但在动手把大包塞进去之前，你必须先搞懂官方计费与限制规则的一个关键转向。

**过去的规则是：只看 gzip 压缩后的体积（不能超 3 MB）。**  
**如今的规则是：只看未经压缩的原始打包总体积（Total Upload Size，不能超 64 MiB）。**

这意味着打包规则变得更加直观、透明。你不需要再在本地反复做复杂的 gzip 压缩模拟，只要在终端运行官方最新的体检指令，就能一眼看穿自己项目的真实承载能力。

1\. 终端体检命令实操

在你的 Workers 项目根目录下，打开终端，输入这行官方推荐的无损体检命令：

npx wrangler deploy --outdir bundled/ --dry-run

让我们拆解一下这两个核心参数的妙用：

**• --dry-run（安全演习开关）：** 它会完整执行所有的编译、混淆与资源打包流程，但**绝不会把代码真正推送到线上环境** ，不会对现网造成任何意外干扰。

**• --outdir bundled/（产物透视镜）：** 它会把最终要上传给 Cloudflare 边缘节点的所有代码、二进制模块与静态依赖，原汁原味地输出到本地的 bundled 文件夹中。

2\. 看懂终端体检报告

命令跑完后，你的控制台底部会打印出类似这样一段关键汇总：

Total Upload: 12.84 MiB / 64 MiB (uncompressed)

✨ Build succeeded! Dry run complete.

只要前面的数值没有突破 64 MiB，恭喜你，你的整个代码包就能顺畅通行全球 300 多个数据中心。你还可以直接点开本地新生成的 bundled/ 目录，清晰查验每一个脚本与内嵌静态文件的实际大小，做到心中有数。

💡 【形象比喻】行李过磅台

\--dry-run 就像机场值机柜台前的自主行李秤。你不需要真正托运护照买票，在进闸机前提前放上去称一称，既不花一分钱，又彻底告别了在登机口被罚款超重的尴尬。

## 重装武器库解禁：过去不敢想的三大场景，现在直接拉满！

有了 64 MiB 的未压缩容量，原本在边缘函数里被视为“禁区”的重装场景，现在全部变成了触手可及的常规武器。对于全栈程序员和独立出海团队来说，以下三大业务场景将迎来彻底的质变：

场景 1：现代全栈框架整包塞入（Next.js SSR / Astro / Hono）

在过去，想在边缘节点上跑 Next.js 服务端渲染（SSR）过程异常折磨，很多人只能委曲求全退化为纯静态导出。

现在，你可以毫无心理负担地把 Next.js Standalone 产物、Remix 或全功能 Hono 应用整包塞入 Workers。复杂的鉴权拦截、动态多语言渲染全部在边缘节点数十毫秒内瞬间完成，用户打开网页丝滑得像在访问本地局域网。

场景 2：WASM 多媒体与离线轻量数据库

WebAssembly（WASM）是现代 Web 技术的性能发动机，但它编译后的二进制产物动辄数兆起步。现在一系列强悍引擎彻底解禁：

• **图片即时处理：** 直接打包 Rust 编译的 Photon 或轻量 Sharp 引擎，几毫秒内完成缩放裁剪；

• **文档动态合成：** 整包引入 pdf-lib，在边缘实时为客户生成动态订单发票与 PDF 合同；

• **离线复杂分析：** 轻量级 SQLite 或 DuckDB-wasm 直接嵌进内存，实现极速多表分析。

场景 3：边缘微型 AI 与本地向量语义检索

出海开发 AI 工具时，很多人的最大痛点就是每次向外部大模型发请求都要掏昂贵的 Token 费与承担数百毫秒网络延迟。

现在借助 @xenova/transformers，你可以把轻量级量化模型打包在 64 MiB 空间里，离用户最近的机房直接本地生成 Embedding 向量，**零额外 Token 费用，毫秒级完成语义匹配！**
