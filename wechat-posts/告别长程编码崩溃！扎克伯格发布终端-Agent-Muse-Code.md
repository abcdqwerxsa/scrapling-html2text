# 告别长程编码崩溃！扎克伯格发布终端 Agent Muse Code

**作者**: 知识发电机
**发布时间**: 2026-08-06 09:57
**原文链接**: https://mp.weixin.qq.com/s/RXogaHynfHudZCrQ_kw3Gw

---

**Muse Code上线：终端Agent能跑24小时不丢进度**

终端里跑着一个大任务，进度过半突然崩了。重启后上下文全没，只能重新讲需求、重新摸仓库结构。这种事在长程编码里太常见。

![](https://r2.jeanjan.kdns.fr/pictures/img-5775983701.jpeg)

今天扎克伯格直接发了Muse Code beta。它是一个终端编程Agent，能在大型仓库里完整接手软件工程任务：规划改动、写代码、验证结果。背后是Muse Spark 1.2，一个专门强化了编码能力的模型更新。核心变化不在单次生成质量，而在它把Agent变成了能长期待在会话里的小队。

**常驻背景Agent，不再每次从零摸仓库**

以前多数终端Agent接到新任务，得重新扫目录、重新读关键文件。仓库一大，这部分开销就很明显。Muse Code换了做法：一组专门的背景Agent在整个会话期间一直活着。它们持续积累上下文，而不是每次任务重新开始。

这带来的直接后果是，多步骤任务里你需要反复提醒的地方变少了。背景Agent已经知道仓库结构和之前的决策，主Agent可以更专注在当前目标上。官方例子里，它能同时处理多个子任务，而不会因为上下文断裂反复踩坑。

技术上，这套设计是简单的主循环加上异步背景Agent。背景Agent在会话生命周期内持续运行，减少重复信息收集。理论上这能压低长任务的延迟，也减少人工干预次数。模型本身和这套harness是一起训练的，目标就是让工具调用更稳、重试更少。

有意思的是，官方给背景Agent起了名字，比如Photon Sphere、Embervault。这些名字本身不重要，但能看出他们在把多Agent协作当成默认工作模式，而不是事后补丁。

**任务大了就拆：并行子Agent跑在隔离worktree里**

当任务规模够大，Muse Code会把工作拆给多个子Agent。每个子Agent跑在独立的git worktree里，你的工作副本完全不动。官方测试里，它同时给一个游戏加了六个功能，没有冲突。

隔离的好处很直接。并行改代码最怕的就是互相覆盖、合并爆炸。worktree把改动隔开，最后再合并，主工作区保持干净。这对大型仓库尤其有用——你不用担心Agent在改A功能的时候把B功能的分支搞乱。

实现上，子Agent是按需fan-out的。主Agent负责规划和协调，子Agent在隔离环境里执行。官方还配了几个默认技能：`/plan`把任务变成需要审批的计划，`/grill`对计划做压力测试，`/goal`直接朝目标推进。这些技能把常见工作流固化进了命令，减少每次重新描述流程的成本。

社区里对这种并行方式有不同看法。有人觉得隔离足够安全，有人担心最终合并成本还是会回来。两种做法都有人在用，看仓库复杂度和团队习惯。

**可审计日志：崩了也能从断点接着跑**

Muse Code把每一次模型调用、工具运行、审批和编辑都先写进本地事件日志，再执行。日志是单一事实来源。崩溃后，它能从日志精确恢复到中断的位置，不用重新prompt，也不会丢已经做完的工作。

这对长程任务几乎是刚需。官方把Muse Spark 1.2丢给一个内核优化任务，让它在NVIDIA Hopper上跑。1000多次工具调用，持续24小时，它在探索阶段之后还在持续找到明显改进。如果没有可恢复机制，这种长度的任务基本没法做。

日志设计也带来可审计性。企业场景里，能看到Agent每一步做了什么、改了哪里，比黑盒输出更可控。重启安全意味着你可以把任务丢给它过夜，不用盯着。

模型侧，Muse Spark 1.2是在1.1基础上专门加了编码训练算力，并扩大了训练环境多样性。它和Muse Code一起做了协同训练，用拒绝采样的轨迹、目标优化、上下文压缩和子Agent相关配方，让模型和这套工具集更合拍。上下文窗口到了1M token量级，长任务可以尽量在一个会话里跑完。

安装很直接。macOS或Linux下一行命令：
```

curl -fsSL https://dev.meta.ai/install.sh | bash
```

装完用Meta账号登录，需要绑定支付方式。有contributor档，起步成本低，但会用你的数据做训练；标准档价格更高，数据不用于训练。跑起来后可以直接给任务，背景Agent会开始积累上下文。

实际用的时候，长任务最好先用`/plan`走一遍审批，再让它执行。并行场景下记得确认worktree隔离是否符合你的仓库规范。日志文件本地可见，出问题可以直接查。

Muse Code现在还是beta，但已经把“能长期跑、能并行、能恢复”这三件事做成了默认能力。对需要在大型仓库里做完整工程任务的人来说，这比单次生成质量更直接解决痛点。
